# Johns

A house chore rota with consequences. "Johns" is what the house calls its
assigned chores for the week; one chore is a **John**.

This is NOT the Next.js you know: v16 has breaking changes. Read
`node_modules/next/dist/docs/` before writing framework code (see AGENTS.md).
`proxy.ts` is this version's middleware; `params`/`searchParams` are
Promises (`PageProps<"/route">` is generated by `next typegen`); Server
Actions refresh the page with `refresh()` from `next/cache`.

## The stack, and where it came from

The same shape as `pub-golf`, `graph-editor` and `home` (glyn.dev): npm,
Next 16.2 + React 19.2, Tailwind 4 (`@theme inline` tokens), `@supabase/ssr`
clients in `lib/supabase/` (`client`, `server`, `proxy`, plus `admin` for the
service role), next-themes with the `.dark` class, lucide icons, sonner, zod,
Vitest (unit + db projects) and Playwright. Vercel and Supabase deploy from
their GitHub integrations; CI only proves.

Components are **shadcn/ui** (radix-nova, `components.json` matches the other
repos). Add new ones with `npx shadcn add <name>`, never hand-roll a primitive
shadcn provides. House customisations live in the generated files: Button's
default size is `min-h-12` (thumb target), Input is `min-h-12`, `FieldLabel`
is exported from `ui/input.tsx`. `ui/native-select.tsx` was written by hand
because the registry was unreachable from the session that scaffolded the
repo; `npx shadcn add native-select` replaces it with the same API. Domain
components (Avatar initials, StatusChip, the John card) stay custom.

## House style: Bin Night

Council signage. Tokens live in `app/globals.css`: pavement and tarmac
grounds, ink, **hi-vis amber** (`--hivis`) for the one thing to do, **hazard**
for late and missed, and a bin-lid colour per kind of John
(`--bin-kitchen`, `--bin-bathroom`, `--bin-bins`, `--bin-floors`,
`--bin-errands`, `--bin-other`, mirroring `CATEGORIES` in `lib/domain.ts`).
Never hardcode colours. Headings are uppercase Overpass (Highway Gothic's
descendant); the wordmark is the name boxed like a road sign (`road-sign`
utility). Late and missed wear `hazard-tape`. No emoji anywhere in the UI:
lucide icons only, reactions included. Light and dark both ship; the theme
follows the system by default.

Responsive, not just mobile-first: `components/shell/app-shell.tsx` is tabs
along the bottom on a phone and a sidebar from `lg` up, where pages spread
into two or three columns (the week board becomes a table). Tap targets are
at least 44px; compact controls appear only in the laptop board.

## Rules live in the lowest layer that can hold them

- **Pure, unit-tested, no clock** (`lib/`): `week.ts` (week and month edges
  in the house's zone, DST-safe, cadence, `graceDue`), `rota.ts` (fair
  shares + carry-over), `outcome.ts` (when a tick stands, live status),
  `points.ts` (the Table), `streak.ts` (streaks, immunity and swap tokens),
  `stake.ts` (forfeits, month settlement, settle-up), `dispute.ts`
  (verdicts), `money.ts`, `format.ts`. Every function takes `now`.
- **The engine** (`lib/engine/tick.ts`): decides with those rules and applies
  each decision through one service-role SQL function that is atomic and
  refuses to apply twice (`deal_week`, `settle_assignments`,
  `resolve_dispute`, `close_week`, `close_month`). It takes the client and
  `now` as arguments and imports nothing server-only, so `tests/db` drives it
  directly. Safe to run concurrently: two ticks racing never double a
  forfeit or a token (tested).
- **RLS and SECURITY DEFINER functions** (`supabase/migrations`): the only
  real enforcement. Housemates READ through RLS (`is_member`) and WRITE only
  through named functions (`mark_done`, `undo_done`, `raise_dispute`,
  `cast_vote`, `use_immunity`, `use_swap`, `confirm_payment`,
  `create_house`, `join_house`, `set_member_role`, `remove_member`) or a few
  column grants (house settings and the John list for admins, your own name,
  reactions, push subscriptions). Refusals raise `42501` (not yours) or
  `P0001` with a short code that `lib/errors.ts` turns into a sentence.
  Server actions in `lib/actions` are thin wrappers: they never decide.

## The clock

pg_cron calls `public.request_tick()` every ten minutes, which POSTs to
`/api/cron/tick` with a shared secret read from Vault (see DEPLOYMENT.md).
That tick deals new weeks, settles outcomes and forfeits, decides disputes,
closes weeks (streaks, perks) and months (the Stake), and sends reminders.
A page load also catches its own house up (`lib/engine/fresh.ts`, at most
once a minute, no pushes), so a screen never shows last week and local dev
needs no cron. Nothing is dealt until an admin presses "Hand out this week's
Johns" (`houses.rota_started_at`); a week can be re-dealt while nothing in it
has been ticked. Dealing part-way through a week gives anything already due
a day's grace (`graceDue`).

## The game

- **Fair shares**: Johns are dealt so effort points even out, counting each
  person's carry-over from the last four weeks against their fair share of
  each; doing the same John twice running costs a small penalty.
- **Housemate check**: a tick stands after `dispute_hours` (default 24)
  unless disputed. Raising a dispute counts as a vote to strike; everyone
  but the ticker votes; a majority decides at once, otherwise the vote closes
  on time and a tie goes to the tick. Upheld strikes the tick: the John is
  open again, and missed if the week has ended.
- **The Table**: on time earns full points, late half, missed nothing.
- **Streaks and perks**: a clean week is every John on time or excused. Every
  4 clean weeks in a row earns an immunity token (cap 2), spent to excuse a
  John with no forfeit. Topping a week earns a swap token (cap 1), spent to
  trade one of your open Johns for any housemate's open John that week.
- **The Stake**: everyone stakes the same each month. Late and missed Johns
  forfeit fixed amounts, capped at the stake; at month end the forfeits are
  shared equally among everyone else. Money is integer minor units in an
  append-only ledger, from each person's side; balances are sums, a month
  always sums to zero, and only the payee can confirm a payment. The app
  never moves money.
- **The Wall**: `events` rows written by the functions and the engine, with
  reactions and photo receipts.

Words: a chore is a **John**; the plural is **Johns**. The money is **the
Stake**, the standings **the Table**, the feed **the Wall**. Copy never
says "chore app".

## Data model (supabase/migrations)

`profiles` (from auth via `handle_new_user`) → `houses` (rules: timezone,
currency GBP/CAD/USD/EUR defaulted from Vercel's geo headers, week start,
stake and forfeits, dispute hours; `join_code` from the CSPRNG) → `members`
(role admin/member, streak, tokens; one house per person via
`members_one_house`, dropped when "more than one house" ships) → `johns` (the
list: category, points 1–10, every N weeks from `anchor_week`, due day and
time, needs photo) → `weeks` (unique per house and local start date) →
`assignments` (a snapshot of the John as dealt, `due_at`, `done_at`,
`photo_path`, `outcome` stamped once final) → `disputes` + `dispute_votes`;
`ledger` + `month_closes`; `events` + `reactions`; `push_subscriptions`.
Photos live in the private `proofs` bucket at `<house>/<assignment>/<file>`.

Migrations must stay additive once anything is deployed, because Vercel and
Supabase deploy independently. A new function must revoke EXECUTE from
`public, anon, authenticated` and grant back only what is meant: the
platform's default privileges hand it to all three. A new table needs its
grants stated the same way, including `service_role`. Regenerate types after
schema changes: `npm run types`.

## Testing

- `npm test`: Vitest `unit` (`tests/unit`). Pure logic only. No stack, no
  network, no clock.
- `npm run test:db`: Vitest `db` (`tests/db`) against the local stack, with
  per-role clients (`tests/support/clients.ts`) and scoped teardown, never
  truncate. `adminClient()` seeds and reads back; it is never the subject. An
  UPDATE that RLS filters returns no error and no rows, so a blocked write is
  proven by re-reading the row. `42501` is a grant or a function's refusal;
  an RLS filter is silence.
- `npm run test:e2e`: Playwright on port 3205, once per row of the matrix
  (Pixel 7, iPhone 15, desktop Firefox, a 1440px laptop). Sessions are minted
  by `e2e/auth.ts`, since Google's consent screen cannot be driven. A pass on
  retry is a failure in CI. Count things by what reads the same in every
  layout (the board is cards on a phone and a table on a laptop), and wait on
  a dialog closing rather than a button's label, which changes while pending.
