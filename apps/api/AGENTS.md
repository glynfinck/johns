## This app (apps/api)

The block above is Next.js's. These rules are specific to this app; the root
AGENTS.md has the project-wide rules (the game, the words, the data, the

Next.js 16.2 on Vercel (the `jonz-api` project, Root Directory `apps/api`), at
api.jonz.app. It serves the `/api` routes (jonz.app passes
`/api/*` on to it), the cron tick and push sending. Its pages served
johns.glyn.dev until the Expo web build took over on 27 October 2026.

**An exception to the template, with an end date.** The app template's API is
route handlers only, with no pages. This one keeps its pages, components and
server actions, which no longer serve the site since the Phase 13
cutover but stay as the rollback (DEPLOYMENT.md), until Phase 14 removes
them (`docs/specs/native-migration.md`). Until then,
fix and extend the web UI here as normal, and make the same change in
`apps/client`: the Expo web build has every page this app serves.
`public/`'s manifest, icons and `sw.js` have copies in `apps/client/public`;
change both.

## Next.js 16 here

- `proxy.ts` is this version's middleware: it only keeps cookie sessions
  fresh, and skips the cron tick, which brings its own secret.
- `params` and `searchParams` are Promises; `PageProps<"/route">` is
  generated by `next typegen` (part of `npm run typecheck`).
- Server Actions refresh the page with `refresh()` from `next/cache`.
- `@app/core` is TypeScript source; Turbopack compiles workspace packages
  itself, so it needs no `transpilePackages`.

## The stack

Tailwind 4 (`@theme inline` tokens), `@supabase/ssr` clients in
`lib/supabase/` (`client`, `server`, `proxy`, plus `admin` for the service
role), next-themes with the `.dark` class, lucide icons, sonner, zod.

Components are **shadcn/ui** (radix-nova, `components.json` matches the other
repos). Add new ones with `npx shadcn add <name>` from this directory, never
hand-roll a primitive shadcn provides. House customisations live in the
generated files: Button's default size is `min-h-12` (thumb target), Input is
`min-h-12`, `FieldLabel` is exported from `ui/input.tsx`.
`ui/native-select.tsx` was written by hand because the registry was
unreachable from the session that scaffolded the repo; `npx shadcn add
native-select` replaces it with the same API. Domain components (Avatar
initials, StatusChip, the John card) stay custom.

## Bin Night on the web

The tokens live in `app/globals.css` (the root AGENTS.md says what they
mean). The wordmark uses the `road-sign` utility; late and missed wear
`hazard-tape`.

Responsive, not just mobile-first: `components/shell/app-shell.tsx` is tabs
along the bottom on a phone and a sidebar from `lg` up, where pages spread
into two or three columns (the week board becomes a table). Compact controls
appear only in the laptop board.

## Where things go

- `app/`: routes. `app/api/cron/tick` is the clock's endpoint: its path is
  stored in production's Vault, so it never moves.
- `app/api/*` besides the tick: route handlers for the native app, the
  template's way. Each is thin: `requireUser` (`lib/auth.ts`: the bearer
  token, checked with Supabase, and a client that acts as the caller), parse
  the body with its schema from `@app/core` (a 400 otherwise), read what it
  needs through the caller's own RLS, then call the engine or an RPC; answer
  with `json` / `error` from `lib/respond.ts` and export `OPTIONS =
  preflight`. Errors are `{ "error": "<sentence>" }`, never a stack or a
  query. CORS only for `ALLOWED_ORIGINS` (`lib/env.ts`): the Expo web build
  on 8205 locally; phones send no Origin. `proxy.ts` doesn't touch `/api/`.
  Today: `POST /api/fresh` (catch a house up, at most once a minute),
  `POST /api/disputes`, `POST /api/disputes/:id/votes`, `POST /api/deal`
  (an admin hands out or re-deals the week), `POST /api/setup/draft`
  (Describe your house: one turn of the setup chat, in which Claude drafts
  and changes a John list for an admin to review,
  `lib/moves/draft.ts` and `lib/ai/house-draft.ts`, the only code that
  calls Claude; `docs/specs/describe-your-house.md`), and
  `POST /api/push-actions` (a button on a notification: the one route with
  no bearer token, because the push's own signed token, `lib/push-token.ts`,
  stands in for it). A database
  refusal answers through `refused`: 403 when it isn't the caller's to make
  (42501), 409 when the rules say not now (P0001), in `humanError`'s words.
- `lib/moves/`: a move that needs the service role after the caller's own
  RPC (tell the house, decide at once), shared by the server action and the
  route so the web and the app can't drift: `disputes.ts` (raise, vote) and
  `deal.ts` (the deal: deal_week is the engine's, so the move itself checks,
  through the caller's own session, that an admin of the house is asking).
- `lib/actions/`: server actions. Thin wrappers around one SQL function or
  column-granted write each: they translate refusals with `humanError` and
  refresh. They never decide.
- `lib/data/`: loaders that read through the user's session (RLS decides).
  They read rows; core's builders (`buildWeekBoard`, `todayView`) shape
  them, so the native app shows the same week from the same rows.
- `lib/engine/`: the tick (`tick.ts`) and the page-load catch-up
  (`fresh.ts`). The only code that uses the service role, apart from the cron
  route and push.
- `lib/push.ts`: Web Push with VAPID, the engine's `Notify`. It reads each
  person's `notification_prefs` (skip a kind they turned off, no sound in
  quiet hours) and gives each push its buttons and that person's token.
- `lib/push-token.ts`: the signed token a push's buttons carry (who, and
  which John or dispute), keyed from the VAPID private key, good for 8 days.
  `lib/moves/push-actions.ts` checks it, then calls `push_action`, which
  makes the move as that person through `mark_done` or `cast_vote`.
- `@app/core` for every rule; nothing here re-implements one.

## Tests

- Route handlers are tested in the db tier, called directly with a real
  bearer token (`tests/db/api-fresh.test.ts`): no token, someone else's
  house, a bad body, and the happy path. `server-only` is stubbed there
  (`tests/support/server-only.ts`). Their pure helpers are unit-tested
  (`tests/unit/api.test.ts`).
- `npm run test:db`: Vitest `db` (`tests/db`) against the local stack, with
  per-role clients (`tests/support/clients.ts`) and scoped teardown, never
  truncate. `adminClient()` seeds and reads back; it is never the subject. An
  UPDATE that RLS filters returns no error and no rows, so a blocked write is
  proven by re-reading the row. `42501` is a grant or a function's refusal;
  an RLS filter is silence. Retries are off: a retried RLS test is a lie.
- `npm run test:e2e`: Playwright on port 3205, once per row of the matrix
  (Pixel 7, iPhone 15, desktop Firefox, a 1440px laptop). It also starts the
  Expo app's web build on 8205 (exported against the same local stack,
  served by `e2e/serve-client.mjs` as a single-page app) for the
  `e2e/client-*.spec.ts` files. Sessions are minted by `e2e/auth.ts`, since
  Google's consent screen cannot be driven: `signInAs` as cookies for this
  app, `signInToClient` into localStorage for the Expo one. A pass on
  retry is a failure in CI. Count things by what reads the same in every
  layout (the board is cards on a phone and a table on a laptop), wait on a
  dialog closing rather than a button's label, which changes while pending,
  and navigate with `gotoSettled` (`e2e/nav.ts`) once the house exists:
  WebKit reports the app's own post-action refresh as a navigation that
  interrupts a bare `page.goto`.
- `npm test` runs this app's `unit` project (`tests/unit`), for its own pure
  helpers when it has any.
