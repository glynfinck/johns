## This app (apps/api)

The block above is Next.js's. These rules are specific to this app; the root
AGENTS.md has the project-wide rules (the game, the words, the data, the
ask-first list).

Next.js 16.2 on Vercel (the `johns` project, Root Directory `apps/api`). It
serves the web app at johns.glyn.dev, the cron tick, push sending, and later
the few `/api` routes the native app needs a server for.

**An exception to the template, with an end date.** The app template's API is
route handlers only, with no pages. This one keeps its pages, components and
server actions until the Expo web build reaches parity (Phase 13 of
`docs/specs/native-migration.md`); Phase 14 then removes them. Until then,
fix and extend the web UI here as normal.

## Next.js 16 here

- `proxy.ts` is this version's middleware: it only keeps cookie sessions
  fresh, and skips the cron tick, which brings its own secret.
- `params` and `searchParams` are Promises; `PageProps<"/route">` is
  generated by `next typegen` (part of `npm run typecheck`).
- Server Actions refresh the page with `refresh()` from `next/cache`.
- `@app/core` is TypeScript source; Turbopack compiles workspace packages
  itself, so it needs no `transpilePackages`.

## The stack

Tailwind 4 (`@theme inline` tokens), `@supabase/ssr` clients in
`lib/supabase/` (`client`, `server`, `proxy`, plus `admin` for the service
role), next-themes with the `.dark` class, lucide icons, sonner, zod.

Components are **shadcn/ui** (radix-nova, `components.json` matches the other
repos). Add new ones with `npx shadcn add <name>` from this directory, never
hand-roll a primitive shadcn provides. House customisations live in the
generated files: Button's default size is `min-h-12` (thumb target), Input is
`min-h-12`, `FieldLabel` is exported from `ui/input.tsx`.
`ui/native-select.tsx` was written by hand because the registry was
unreachable from the session that scaffolded the repo; `npx shadcn add
native-select` replaces it with the same API. Domain components (Avatar
initials, StatusChip, the John card) stay custom.

## Bin Night on the web

The tokens live in `app/globals.css` (the root AGENTS.md says what they
mean). The wordmark uses the `road-sign` utility; late and missed wear
`hazard-tape`.

Responsive, not just mobile-first: `components/shell/app-shell.tsx` is tabs
along the bottom on a phone and a sidebar from `lg` up, where pages spread
into two or three columns (the week board becomes a table). Compact controls
appear only in the laptop board.

## Where things go

- `app/`: routes. `app/api/cron/tick` is the clock's endpoint: its path is
  stored in production's Vault, so it never moves.
- `lib/actions/`: server actions. Thin wrappers around one SQL function or
  column-granted write each: they translate refusals with `humanError` and
  refresh. They never decide.
- `lib/data/`: loaders that read through the user's session (RLS decides).
- `lib/engine/`: the tick (`tick.ts`) and the page-load catch-up
  (`fresh.ts`). The only code that uses the service role, apart from the cron
  route and push.
- `lib/push.ts`: Web Push with VAPID, the engine's `Notify`.
- `@app/core` for every rule; nothing here re-implements one.

## Tests

- `npm run test:db`: Vitest `db` (`tests/db`) against the local stack, with
  per-role clients (`tests/support/clients.ts`) and scoped teardown, never
  truncate. `adminClient()` seeds and reads back; it is never the subject. An
  UPDATE that RLS filters returns no error and no rows, so a blocked write is
  proven by re-reading the row. `42501` is a grant or a function's refusal;
  an RLS filter is silence. Retries are off: a retried RLS test is a lie.
- `npm run test:e2e`: Playwright on port 3205, once per row of the matrix
  (Pixel 7, iPhone 15, desktop Firefox, a 1440px laptop). Sessions are minted
  by `e2e/auth.ts`, since Google's consent screen cannot be driven. A pass on
  retry is a failure in CI. Count things by what reads the same in every
  layout (the board is cards on a phone and a table on a laptop), wait on a
  dialog closing rather than a button's label, which changes while pending,
  and navigate with `gotoSettled` (`e2e/nav.ts`) once the house exists:
  WebKit reports the app's own post-action refresh as a navigation that
  interrupts a bare `page.goto`.
- `npm test` runs this app's `unit` project (`tests/unit`), for its own pure
  helpers when it has any.

## Environment

Copy `.env.example` to `.env.local` in this directory and fill it in from
`supabase status -o env`. The db and e2e suites read the same file. Never
commit real values.
