## This app (apps/api)

The block above is Next.js's. These rules are specific to this app; the root
AGENTS.md has the project-wide rules (the game, the words, the data, the
ask-first list).

Next.js 16.2 on Vercel (the `jonz-api` project, Root Directory `apps/api`), at
api.jonz.app. It serves the `/api` routes (jonz.app passes
`/api/*` on to it), the cron tick and push sending, and nothing else: route
handlers only, as the app template intends. Its pages served johns.glyn.dev
until the Expo web build took over on 27 October 2026, and Phase 14
(`docs/specs/native-migration.md`) removed them on 28 October. Every page
lives in `apps/client` now.

Any path outside `/api` answers with a 308 to the same path on
https://jonz.app (`next.config.ts`), so an old link still lands somewhere.
An `/api` path no route claims answers a JSON 404
(`app/api/[...path]/route.ts`). Don't add pages, layouts or `public/` files
here: they would never be reached.

## Next.js 16 here

- There is no `proxy.ts` (this version's middleware): nothing here reads a
  cookie session. The cron tick brings its own secret, and the app's routes
  a bearer token (`lib/auth.ts`).
- `params` is a Promise; route types are generated by `next typegen` (part
  of `npm run typecheck`).
- `@app/core` is TypeScript source; Turbopack compiles workspace packages
  itself, so it needs no `transpilePackages`.

## The stack

`@supabase/supabase-js` clients in `lib/supabase/` (`user` acts as the
caller, `admin` is the service role), zod schemas from `@app/core`,
web-push.

## Where things go

- `app/`: routes. `app/api/cron/tick` is the clock's endpoint: its path is
  stored in production's Vault, so it never moves.
- `app/api/*` besides the tick: route handlers for the native app, the
  template's way. Each is thin: `requireUser` (`lib/auth.ts`: the bearer
  token, checked with Supabase, and a client that acts as the caller), parse
  the body with its schema from `@app/core` (a 400 otherwise), read what it
  needs through the caller's own RLS, then call the engine or an RPC; answer
  with `json` / `error` from `lib/respond.ts` and export `OPTIONS =
  preflight`. Errors are `{ "error": "<sentence>" }`, never a stack or a
  query. CORS only for `ALLOWED_ORIGINS` (`lib/env.ts`): the Expo web build
  on 8205 locally; phones send no Origin.
  Today: `POST /api/fresh` (catch a house up, at most once a minute),
  `POST /api/disputes`, `POST /api/disputes/:id/votes` and `POST /api/deal`
  (an admin hands out or re-deals the week). A database
  refusal answers through `refused`: 403 when it isn't the caller's to make
  (42501), 409 when the rules say not now (P0001), in `humanError`'s words.
- `lib/moves/`: a move that needs the service role after the caller's own
  RPC (tell the house, decide at once): `disputes.ts` (raise, vote) and
  `deal.ts` (the deal: deal_week is the engine's, so the move itself checks,
  through the caller's own session, that an admin of the house is asking).
- `lib/engine/`: the tick (`tick.ts`) and the page-load catch-up
  (`fresh.ts`). The only code that uses the service role, apart from the cron
  route and push.
- `lib/push.ts`: Web Push with VAPID, the engine's `Notify`.
- `@app/core` for every rule; nothing here re-implements one.

## Tests

- Route handlers are tested in the db tier, called directly with a real
  bearer token (`tests/db/api-fresh.test.ts`): no token, someone else's
  house, a bad body, and the happy path. `server-only` is stubbed there
  (`tests/support/server-only.ts`). Their pure helpers are unit-tested
  (`tests/unit/api.test.ts`).
- `npm run test:db`: Vitest `db` (`tests/db`) against the local stack, with
  per-role clients (`tests/support/clients.ts`) and scoped teardown, never
  truncate. `adminClient()` seeds and reads back; it is never the subject. An
  UPDATE that RLS filters returns no error and no rows, so a blocked write is
  proven by re-reading the row. `42501` is a grant or a function's refusal;
  an RLS filter is silence. Retries are off: a retried RLS test is a lie.
- `npm run test:e2e`: Playwright against the Expo app's web build on 8205
  (exported against the local stack, served by `e2e/serve-client.mjs` as
  Vercel serves it), with this app on 3205 behind its `/api/*`, once per row
  of the matrix (Pixel 7, iPhone 15, desktop Firefox, a 1440px laptop). The
  suites live here because this app owns the stack's settings; they are the
  `e2e/client-*.spec.ts` files. Sessions are minted by `e2e/auth.ts`
  (`signInToClient`, into localStorage), since Google's consent screen
  cannot be driven. A pass on retry is a failure in CI. Count things by what
  reads the same in every layout (the board is cards on a phone and a table
  on a laptop), and wait on a dialog closing rather than a button's label,
  which changes while pending.
- `npm test` runs this app's `unit` project (`tests/unit`), for its own pure
  helpers when it has any.

## Environment

Copy `.env.example` to `.env.local` in this directory and fill it in from
`supabase status -o env`. The db and e2e suites read the same file. Never
commit real values.
